Cómo usar esta guía. El repo papus-discord ya es la plantilla: casi todo lo que cambia de un proyecto a otro vive en archivos de config/ y content/. Para un servidor nuevo se copia el repo, se cambian esos archivos y se siguen los pasos de la sección 3. El código solo se toca si el nuevo proyecto necesita algo distinto.

1. La idea en una página

Un servidor de Discord gratis para la comunidad, con personajes que conversan (bots con personalidad propia), niveles de pago en Ko-fi que abren canales extra, y la mayor parte del trabajo diario automatizado.

💬 Discord

  • Una app de Discord por personaje
  • Canales por nivel, roles, AutoMod
  • Encuestas nativas, menús, mensajes fijados

🖥️ PC (Windows)

  • Los bots conectados (conversación, moderación, bienvenidas)
  • Calendario, vitrina, roles automáticos
  • Modelo local (Ollama) de respaldo
  • Arranca solo con Windows

☁️ Cloudflare (gratis)

  • Worker 24/7: comandos de 2 bots
  • Base D1: pedidos, votaciones, candidatos
  • Cron cada 15 min: abre y cierra votaciones

☕ Ko-fi

  • Niveles mensuales → rol de Discord automático
  • Tienda: videos personalizados, entrada gratis
  • Metas del perfil

🧠 LLM gratuitos

  • Groq, Gemini, OpenRouter, Cloudflare AI
  • Se turnan según su cupo diario
  • El modelo local, de respaldo

📁 Google Drive

  • Bóveda y archivo privados
  • Acceso por Gmail, sin descargas

Reparto de trabajo: lo que necesita estar siempre disponible (comandos de pedidos y votaciones, menú de colores) vive en Cloudflare. Lo que necesita leer archivos del PC o escuchar todos los mensajes (conversación, moderación, calendario) corre en el PC. Si el PC se apaga, AutoMod de Discord sigue moderando lo grave.

3. Paso a paso para un servidor nuevo

1
Copiar el repo a una carpeta nueva y npm install. Copiar .env.example a .env y llenarlo.
2
Personalizar los archivos de la sección 9: estructura del servidor, personajes, frases, guías, moderación, votaciones y calendario.
3
Revisar todo: npm run check (llaves y APIs) y npm run check -- --llm (la voz de cada personaje en cada API). npm test debe quedar en verde.
4
Armar el servidor: npm run servidor muestra el plan; npm run servidor -- --apply crea roles, categorías, canales y permisos (nunca borra). Se puede correr las veces que haga falta.
5
Perfiles y guías: npm run avatares + npm run perfiles (avatar, banner, biografía); npm run guias -- --apply publica y fija la guía de cada canal (si ya existe, la edita).
6
Emojis: generar con los scripts de Python y subir con npm run emojis.
7
Worker de Cloudflare: npm run worker:deploy crea la base D1, aplica el esquema, guarda los tokens como secretos, publica y registra los comandos de sus bots.
8
Arranque con Windows: npm run autostart (bots), npm run bandeja (ícono) y, como administrador, npm run despedida-al-apagar.
9
Ko-fi: textos de niveles, bienvenidas, términos y tienda (plantilla en docs/KOFI.md); en cada nivel, su rol de Discord.
10
Revisión final con la checklist de la sección 10 y commit de respaldo (idealmente subido a un repo privado).

4. Diseño del servidor

Categorías por nivel, acumulativas

Cada categoría de pago la ve su nivel y todos los superiores (Ko-fi da solo el rol del nivel; los permisos hacen la suma). Dentro, cada canal es "solo lectura" (publica GyroP o un bot) o "escriben todos los que leen".

PiezaPara qué sirve
Inicio (solo lectura)Bienvenida, reglas, anuncios, niveles, vitrina, elegir color, novedades, salón de la fama.
ComunidadCharla, fanart, memes, recomendaciones, hablar con los bots, eventos, ideas, comandos de bots y reportes.
Una categoría por nivelLo que promete cada nivel en Ko-fi, ni más ni menos.
Canales candado 🔒Un canal por nivel que solo ven quienes no lo tienen, con un mensaje fijado de lo que hay detrás. Discord no permite "ver sin entrar"; esto es lo más parecido, sin filtrar nada.
👀 VitrinaLos bots avisan dónde y para quién hay algo nuevo (nunca qué): motiva a subir de nivel.
Sala para un rol especialCategoría visible solo para un rol que no se compra (p. ej. "Papu de honor"), con chat, votación y voz.
StaffModeración, registro de los bots, pruebas. Nadie más la ve.

Roles

Automáticos

  • Rol de todos (sin color): lo da un bot al entrar, con repaso cada hora.
  • Fundador: a quien tenga nivel en la primera semana, para siempre.
  • Niveles: los da Ko-fi.

Otros

  • Colores elegibles: un menú con una paleta que no use los colores de los niveles.
  • Rol de honor: a mano, por participación.
  • Bots de música: agrupados, sin acceso a canales de texto (salvo el de comandos).

Permisos: lo que no hay que olvidar

  • Discord deja "Mencionar @everyone" activado en @everyone y en cada rol nuevo. npm run servidor lo quita (también administrar, moderar, expulsar) y crea los roles sin permisos.
  • Los bots necesitan Gestionar roles en su propio rol para dar roles, y estar por encima de los roles que dan.
  • Un canal de encuestas visible es un canal donde se puede votar: no se abren los de votación a quien no paga.
  • El bot con Administrador temporal se baja a lo mínimo al terminar (conservando Gestionar roles).

5. Los bots

Personalidad

  • Una ficha por personaje (content/personajes/*.md) + reglas comunes (comun.md): cómo habla, frases de ejemplo, canciones favoritas, cómo trata a los demás, y una lista de temas de humor de la que se elige uno al azar en cada respuesta (los pegajosos se marcan con ! para que no se repitan).
  • Datos de personaje desde una fuente (el lore del motor) y datos de cultura general (cultura.md): solo se mandan los 3 que tienen que ver con la pregunta.
  • Reglas de trato que funcionaron: contestar primero y bromear después; empatía si alguien cuenta algo malo; nunca a la defensiva; no repetir muletillas; tutear y no adivinar el género; reconocer al dueño por su id, no por el nombre.

Cuota y frases fijas

  • Cuota diaria única por persona, compartida entre todos los bots e igual para todos los niveles (pagar no da más mensajes). Una unidad por cada @. Se devuelve si la respuesta falla.
  • Todo lo que no es conversación libre (bienvenidas, avisos, cuota agotada, moderación, votaciones) usa grupos de 30-40 frases fijas que no se repiten hasta agotar el mazo. Nunca gastan cuota.

LLM: varias APIs gratis que se turnan

  • Una interfaz única compatible con OpenAI y una cadena de respaldo: cada mensaje va a la API con más cupo del día; si una falla, se demora, bloquea por minuto o devuelve algo ilegible, responde la siguiente. El modelo local queda de respaldo.
  • Varios mensajes con @ a la vez → una sola petición que devuelve un JSON con la respuesta de cada personaje.
  • El estado del día (porcentaje por API) se ve en el ícono de la bandeja.

Privacidad del proceso

Tres capas para que los bots nunca revelen herramientas ni métodos de producción: preguntas detectadas → frase fija; regla en el prompt; y un filtro de salida que descarta la respuesta si menciona algo de la lista privada. De los videos, los bots solo conocen título y estado de las carpetas autorizadas.

Moderación

  • Reglas fijas, nunca el LLM: odio y groserías fuertes siempre fuera; insultos solo si van dirigidos a alguien; datos personales; estafas e invitaciones; flood; mensajes repetidos.
  • Strikes: advertencia → 10 min → 1 hora → 1 día y aviso al dueño. Vencen a los 3 días. El bot nunca expulsa ni banea.
  • AutoMod de Discord se sincroniza al arrancar y cubre lo grave aunque el PC esté apagado.
  • Empezar permisivo con enlaces (lista amplia de sitios, restricción solo la primera hora para cuentas nuevas) y con mayúsculas (solo mensajes largos, solo aviso).

6. Membresías y comunidad

Ko-fi

  • Niveles acumulativos, cada uno con lo que da (beneficios concretos, sin promesas que no se van a cumplir cada semana). Etiquetas de Ko-fi coherentes con los beneficios (nada de "Merchandise" si es digital).
  • Entrada gratis como producto de $0 en la tienda: entrega el enlace de invitación (los productos no dan roles).
  • Fundador por tiempo limitado como gancho de lanzamiento.
  • El rol llega solo si la persona conecta su Discord en su cuenta de Ko-fi. Un rol dado a mano no lo quita Ko-fi al cancelar: anotarlo.
  • Plantilla completa de textos (niveles, bienvenidas, términos, tienda, metas) en docs/KOFI.md.

Votaciones (encuestas nativas de Discord)

Semanal de pago

Se abre sola. Opciones: el segundo lugar de la semana anterior + candidatos nuevos de una lista de espera. Recordatorio 12 h antes, anuncio del ganador, empate → decide el dueño. Se anuncia en la vitrina.

Sala de honor

Cada 2 semanas. Opciones: videos ya listos + las 2 ideas con más 👍 del chat (sin contar el voto propio ni bots, sin repetir ideas).

Calendario y contenido

  • Ritmo: 3 videos por semana — lunes el que eligió la votación de pago, miércoles el del creador, viernes alternando entre el rol de honor y el creador.
  • Calendario automático fijado de 2 semanas: ganadores, opciones en votación ("Video de A / B / C") y videos propios tomados de la carpeta de finales en orden. Se edita solo.
  • Bóveda y archivo en carpetas de Drive restringidas: acceso por Gmail enviado en privado; sin descarga para lectores; al cancelar, quitar el acceso.
  • Pedidos personalizados del nivel más alto: comando para pedir, cola con tablero fijado (sin el nombre del destinatario), estados con aviso al pedidor y alertas de plazo.
  • Tips con fuente y Salón de la Fama cuando un tip llega a un video.

Bienvenidas, rol de todos, FundadorPCAl entrar y en un repaso cada hora (Discord a veces no avisa una entrada).

CalendarioPCCada hora; lee la carpeta de finales y la base D1.
Avisos de reportesPCCada mensaje en #reportes llega con enlace al registro del staff.

8. Lecciones aprendidas

TropiezoSolución
Todos podían mencionar @everyoneQuitar ese permiso a @everyone y a todos los roles; crear roles sin permisos.
Bots "a la defensiva" o que dicen "no sé"Permitir cultura general con datos verificados; prohibir muletillas por escrito; quitar ejemplos que el modelo copia.
Un tema "prohibido" bloqueaba la pregunta directa (el puerro)Si la persona nombra el tema, ese es el tema de la respuesta.
Respuestas que fallaban a ratosUn modelo "pensaba" de más y cortaba la respuesta: pensar lo mínimo y, si llega ilegible, pasar a la siguiente API.
Groq bloquea por minutoTurnar las APIs y saltar a la siguiente; la cuota protege del exceso.
Se borraban GIFsEl buscador de Discord usa Klipy: ampliar sitios permitidos y acortar la restricción de cuentas nuevas.
Rol de Ko-fi que no llegóLa persona no conectó Discord en Ko-fi; el rol manual no se quita solo al cancelar.
Roles con el mismo nivel en la listaUn rol sin color no tapa el color elegido; no depender del orden si se puede evitar.
"Pensando…" para siempre en comandosReintento si Discord aún no registró la respuesta, tope de tiempo y mensaje aparte de respaldo.
Probar con "usuarios falsos"Los self-bots están prohibidos; probar con webhooks en un canal de staff o con simulaciones.
PowerShell agrega una marca invisible (BOM)Escribir archivos de configuración con Node o el editor, no con Set-Content.
Ko-fi bloquea lectores automáticosLeer los datos que la página carga por detrás (tienda) o pedir una captura.

config/especiales.jsonExcepciones personales decididas por el dueño.

Si el proyecto no tiene un "motor de videos": el lore puede venir de un archivo propio (como content/lore-extra.json), y el calendario y el catálogo de videos se pueden apagar dejando vacías sus rutas.

10. Checklists

🚀 Antes de abrir

  • Tokens y llaves en .env; npm run check en verde
  • npm test en verde
  • Servidor aplicado; segunda pasada sin cambios pendientes
  • Nadie con "Mencionar @everyone" ni permisos de moderar
  • Guías fijadas en todos los canales
  • Perfiles, avatares y emojis de los bots
  • Worker desplegado y comandos registrados
  • Ko-fi: textos, rol por nivel, rol del bot de Ko-fi arriba
  • Invitación permanente en Ko-fi y en la entrada gratis
  • Carpetas de Drive restringidas
  • Arranque con Windows, ícono y despedida al apagar
  • Revisar visibilidad real de cada tipo de miembro
  • Commit de respaldo (y subido a un repo privado)

🔁 Mantenimiento

  • Diario: mirar #registro-bots y #reportes; consumo de APIs en el ícono
  • Diario: revisar conversaciones (npm run conversaciones) y corregir fichas
  • Semanal: candidatos para la votación y videos listos para la de honor
  • Semanal: revisar el calendario fijado
  • Mensual: accesos de Drive vs. miembros activos; roles dados a mano
  • Mensual: metas de Ko-fi y beneficios prometidos
  • Al cerrar la configuración: quitar Administrador al bot (dejar Gestionar roles)
Para seguir creciendo: el plan completo y todas las decisiones están en docs/PLAN.md; el uso diario, en README.md; las reglas para trabajar en el repo, en CLAUDE.md. Esta guía se regenera con node scripts/render-guia.mjs.
